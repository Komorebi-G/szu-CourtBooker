# 桌面版使用与构建

深圳大学体育场馆预约助手。网页用于管理任务，当前助手进程负责本次预约，日志和结果保存在本机。预约使用已经打通的学校 HTTP 接口，浏览器仅用于人工登录。

本文命令均在仓库根目录执行。返回 [项目首页](../README.md)。

## 启动

### Windows 单文件版（推荐日常使用）

双击 `dist/SZU-CourtBooker.exe`，无需安装 Node.js、npm、Python 或项目依赖。程序内置运行时，约 93 MiB；首次运行自动解压应用缓存，期间显示启动提示，管理页面随后在预约助手专用浏览器配置中打开，默认优先 Edge。学校登录可在账号管理中选择 Edge、Chrome、Brave 或 Chromium；各浏览器使用独立的助手配置。选错时点击「取消登录」，重新选择即可。exe 使用 Windows GUI 子系统，后台预约不弹黑色终端。

请先把 exe 放在 Windows 本地盘的固定位置，再保存方案。账号、配置、任务和日志保存在 `%LOCALAPPDATA%\SZUCourtBooker`，不在 exe 旁边。包内不包含你的 Cookie 或已有任务。旧版用户可在账号管理导出登录 JSON，然后在 exe 版导入；原任务仍在旧数据目录，不会自动迁移或重复安排。构建尚未代码签名。

### 源码运行（Windows / Linux / WSL）

需要 Node.js 22 或更新版本。首次安装依赖：

```bash
npm install
```

日常 Windows 原生运行（项目放在 Windows 本地盘）双击 `start.cmd`；Linux/WSL 执行 `bash start.sh`。当前项目位于 WSL 时继续从 WSL 启动，界面由 Windows Edge 打开。也可以直接运行，日常不需要 npm：

```bash
node src/web-server.js
# 不自动打开浏览器：
node src/web-server.js --no-open
```

默认使用 <http://127.0.0.1:4173>。端口被旧版、其他程序或不同数据目录的实例占用，或被系统拒绝绑定时，会自动换用可用端口并打开正确地址；请以新启动程序打开的页面为准，不要一直刷新旧书签。Windows 源码启动入口也支持项目内 `runtime/node.exe`。

普通 Windows/Linux 默认监听回环地址；WSL 为兼容 Windows localhost 转发监听 `0.0.0.0`。本版没有远程访问认证，不应暴露到公网。界面支持手机宽度，但手机远程管理、HTTPS 和身份验证属于后续扩展。

同版本、同数据目录且页面资源正常的管理实例才会复用，因此不同位置的同版 EXE 不会重复启动管理服务。旧版实例不会被强制关闭，升级前请先停止旧版本中的执行。EXE 启动会校验自己的解压缓存，缺失、损坏或未完成解压的程序文件会自动修复；不会清空账号、配置和执行记录。

## 临场使用

1. 提前新建并保存方案：选择用户、日期、项目、预约目标、候选时段和场地顺序；可直接上移 / 下移场地，刷新目录。保存不会执行。
2. 放号当天、临近 12:30 时打开助手，在账号管理验证或重新登录。Cookie 会失效，上次验证成功不表示现在仍有效。
3. 点击「开始倒计时 / 立即尝试」或表单的「保存并启动」，确认后再次联网验证身份和学校日期接口。未放号时进入倒计时；已放号则立即尝试。更早日期只允许保存方案，不进行隔夜等待。
4. 放号前最后 15 秒复核学校身份和已有预约，在准备窗口内预读候选时段、提前保存首单意图；临近放号再次估计学校时钟偏差，到点提交首选。准备时目标目录尚未开放或为空，则到点重读。失效或订单状态无法确认时停止相关尝试。通过后按场地顺序尝试，连续时段可优先同场。同账号、项目、日期的学校有效预约与本批次新成功合计最多两个时段；同一学校账号串行提交，不同账号独立并行，未知响应只停止对应账号。本地记录保存失败会停止全部执行。
5. 在卡片查看成功结果，日志可查看各时段结果与导出诊断记录；学校付款仍需自行完成。停止后已成功预约保留。

场地列表先汇总各参考日期与此前读到的有效时段，再在每个已开放参考日期补查这些时段，并保留此前读到的场地和时段；满员或暂不可用的条目仍可作为方案候选。页面显示参考日期及是否含历史目录；它不保证目标时段有空位。正式执行逐时段查询目标日期并及时尝试，不等待全部后续时段目录，空目录在执行窗口内重试，已开始的时段自动跳过。结果区分全部成功、部分成功、名额上限跳过、时段过期、未约到和执行错误。账号异常或学校明确但无法识别的业务拒绝会显示原始原因，并阻止同账号、项目、日期的其他方案继续提交；已发送但结果未知的请求需先到学校“我的预约”核对。

卡片「更多」内的「检查配置」只读身份、目录等，不下单。已完成预约优先显示「查看结果」，重新安排可用「再约一次」；重试前使用「核对并生成剩余方案」查询学校预约，匹配的请求另记为已核实，未对应请求需人工确认，另存剩余候选；修改过方案时可在执行记录中「核对此次执行」，使用当时的方案快照；查询失败不能当作空订单，未知结果须人工核对。修改方案后旧结果留在历史日志，新版方案显示未启动；配置检查与真实预约结果分开显示。

每轮尝试后的等待间隔最小 0.1 秒，持续时间最多 24 小时。提供「放号抢场设置」和「慢速捡漏设置」，也可展开调整重试设置。学校固定在预约日期前一天北京时间 12:30 放号；自定义系统开始时间已经移除。保存的旧 `startAt` 不再用于启动。

新增用户时，浏览器若沿用已有学校会话，先显示姓名和学号尾号，确认绑定后才保存。重复学校身份会拒绝绑定；已有重复登录可先清除其中一份，再使用原用户。启动验证不会拖住其他账号的启动；验证期间关闭确认 / 返回会取消这次启动。页面会自动重连，断线时显示最后同步时间，倒计时仅为本地估算；可点击重新连接。右上角可开启结果提醒。

预约目标支持任选一段、连续两段和任意两段。任意两段的候选中必须有两个互不重叠的时段；未指定目标的旧单段方案按任选一段解释。连续目标可能只成功一段，不自动退订。剩余方案可继承学校已确认的相邻场地偏好。日志含参数、逐请求事件、耗时、选择原因、结果与匿名账号分组，导出过滤凭据和订单号字段；每次执行追加日志最多 8 MiB，界面最近 500 条，容量截断会明确说明。首页轮询仅返回执行摘要，打开记录后按需读取日志。

## 工作台

首次使用按「登录账号 → 新建方案 → 手动启动」显示当前步骤；未建方案时只突出一个下一步入口，隐藏空列表的搜索和筛选。首次保存后提示在卡片手动开始，执行过后引导自动收起。已有方案时首页以方案列表为主，登录、正在执行和待处理结果各显示简短提示。卡片按上海日期和放号时间显示启动按钮；上次身份验证不表示当前仍有效。宽屏采用双列卡片，窄屏自动切换为单列。

列表默认展示近期方案，进行中的执行和待核对结果排在前面。使用「全部」查看过去的方案，再用「再约一次」保留偏好并确认日期。搜索可匹配名称、日期、项目、时段和已保存场地名称，账号筛选可与状态和搜索组合使用。编辑与当前主要操作放在卡片上；复用、检查配置、删除、历史日志与生成剩余方案放在「更多」里。场地完整顺序、放号时间与重试参数可展开「方案详情」查看，刷新保留展开状态。菜单支持点击外部或 Esc 收起，并根据屏幕空间向上展开。

新建方案优先选有登录文件的账号，表单实时显示选择汇总；未来日期只显示保存入口。按 Esc 或关闭编辑器不会保存或启动。界面模块只提供 `/experience.js`，不对外提供共用源码目录；重新打开助手时也检查该模块是否存在。

## 运行与退出

本次执行在当前助手进程中运行，不启动独立后台预约进程，不注册 Windows 任务计划或 systemd 定时器。请保持电脑醒着、联网、助手运行；休眠或断网可能错过机会，不承诺唤醒与补跑。

- 关闭网页标签：助手进程与已手动启动的本次执行继续。重新双击 EXE 可打开管理页面查看进度。
- 「停止本次执行」：停止该次后续尝试，等待已经发出的请求返回并保存。
- 网页右上角「···」菜单内的「退出助手」、Windows 托盘图标右键「退出并停止执行」，或终端 Ctrl+C：停止全部本次执行后退出助手。
- 进程崩溃、关机、重新启动：只读取历史记录，不自动恢复预约。核对学校结果、更新登录、移除已约时段后手动启动新执行。

## 旧版本迁移

更新前先在旧版本停止正在执行的任务。新版首次打开会给当前数据目录的旧系统定时任务写停止标记，再尝试删除系统定时项；即使系统清理失败，停止标记也会保留，页面会显示重试提示。

旧 `src/dispatcher.js` 入口只清理旧定时；旧 `src/job-worker.js` 入口不再自动预约。方案、账号、成功结果与待核对请求保留。日志可删除到 `.data/trash/`，不会取消学校订单。其他数据目录、旧程序副本及正在运行的旧进程不会随本次源码修改自动升级，需分别停止。

## 源码结构

| 文件 | 职责 |
|---|---|
| `desktop/web/` | 方案、登录、本次执行与历史结果界面 |
| `desktop/src/web-server.js` | 管理 API、执行入口与退出 |
| `desktop/src/execution.js` | 当前进程的执行列表、取消、共享队列与名额 |
| `desktop/src/job-worker.js` | 单次手动执行、状态与预约结果落盘 |
| `desktop/src/jobs.js` | 记录保存、停止、旧定时项迁移 |
| `desktop/src/native-scheduler.js` | 只保留旧系统任务删除功能 |
| `desktop/src/dispatcher.js` | 旧系统入口兼容，不执行预约 |
| `shared/` | 与 Android 共用的协议、会话与预约规则 |

## 验证与构建

```bash
npm run check
npm run build:windows
# 旧入口停用检查：不注册系统任务，不访问学校
node scripts/verify-native-scheduler.js
# 在专用 Windows Edge/CDP 9334 中运行模拟 UI 检查
node scripts/verify-ui.js
```

Windows 构建需要与当前 Node 同版本的 Windows x64 `node.exe`，可用 `SZU_WINDOWS_NODE` 指定路径。安装包输出到 `dist/`。构建后可运行 `node scripts/verify-packaged.js` 检查自包含运行、账号隔离、退出和旧入口停用，不访问学校。

`SZU_CONFIG`、`SZU_SESSION`、`SZU_DATA` 用于指定独立数据路径；`PORT` 或 `--port` 指定端口。UI 测试支持 `SZU_UI_URL`，所有 API 都被模拟，截图在 `output/playwright/`。

CLI 的登录检查、目录、订单查询与配置检查仍可使用；正式预约应从网页「开始本次执行」启动。学校会话寿命和真实预约效果尚待现场验证。
