# 深大场馆预约 · Android 前台版

当前版本 **1.5.8**。满员场地等待实时空位；明确频率拒绝采用账号共用退避。发行附件位于仓库根目录 `dist/release/`，版本与构建标识见 `release.json`。

安装 `dist/SZU-CourtBooker-Android.apk`。安装包自带界面和执行逻辑，不需要电脑、服务器、Node 或 npm。当前为开发签名测试包，未上架商店；iOS 原生适配尚未实现。

GitHub 发行附件名为 `SZU-CourtBooker-Android-debug.apk`。返回 [项目首页](../README.md)。

## 使用

需要 Android System WebView 109 或更新版本；组件过旧时会提示更新。

1. 首页点击「登录学校账号」，在学校页面完成登录后自动返回并验证身份，无需再点「完成登录」。首次登录成功后直接进入新建预约；「检查登录」恢复同一已绑定账号后直接提示成功。
2. 选择运动、日期和一至两个时段。时段与场地自动加载，默认「不限场地」；有场地偏好时直接点击对应场地。
3. 点击「下一步」核对预约内容，再点击「开始预约」。尚未放号时自动等到当天 12:30，已放号时立即尝试。未来开放日的设置只保存，开放当天再开始。
4. 预约期间保持 App 在前台、屏幕亮着；切换 App 或锁屏会中断，返回后不自动续跑。
5. 在「记录」查看结果，到学校系统核对和付款。结果待确认时先核对，不直接重复提交。

名称、目标、同场偏好、重试参数和手动时段放在「更多设置」，普通预约无需调整。首次使用只有一个账号时不显示账号选择；多个账号时可在新建预约中选择。登录失效后从「账号」重新登录。导入和导出登录文件在账号的次级操作中。

## 已保存的预约与记录

卡片直接显示日期、时段和场地，主按钮用于开始、重新预约、继续预约或查看结果。卡片菜单可修改、换日期再约或删除本地设置；这些操作不取消学校订单。旧设置及记录保留，编辑和复用时保留原有偏好，修改后不把旧日期的结果当成新预约结果。

「查找与批量预约」提供搜索、历史筛选和主动进入的批量选择，普通卡片不显示复选框。批量开始也自动按各预约的开放时间处理。「记录」保留成功、部分成功、未约到和需要核对的请求，诊断导出与删除位于记录菜单，付款仍在学校系统完成。

诊断弹窗可复制完整内容或「保存完整文件」。复制成功、复制失败和保存结果直接显示在弹窗内；长日志建议保存 JSON 文件，避免粘贴时内容不完整。保存文件在本次预约结束后进行，已有记录无需重新预约即可导出。

未约到可直接在原任务点击「重新预约」，部分成功点击「继续预约」。开始前自动查询学校订单，跳过已约时段，只尝试仍需预约的候选，不创建另一份剩余预约。仅已发出而结果未知的请求显示「刷新结果」；学校仍未对应确认时，到学校查看订单，确认没有订单和在途请求后，可从记录菜单「学校确认未预约」解除该请求，再在原任务重试。

学校账号、同一项目、同一天的有效预约与本次新成功合计最多两个时段。登录和学校订单在开始前核对；立即执行复用五秒内、统一认证票据未改变的已验证身份，倒计时临近放号仍强制复验。校时优先复用刚收到的身份与目录响应；订单每页最多读取 500 条，服务端限页时按实际大小继续分页。查询失败或响应不明确时停止相关尝试并保留原因，未知请求须先人工核对。空目录和暂时无空位会在设定窗口内继续尝试。不会自动付款、退订、后台定时或后台保活。

任选一段逐个尝试，成功即停；两段目标也逐段查询、提交并保存结果，首段无空位时继续检查后段。任意两段先选互不重叠候选，连续两段先选相邻候选。多个场地且优先同场时，先确定已成功场地，再用它调整相邻时段的顺序。放号前可将两段首选意图分别预先保存，到点复用；立即预约先核对学校订单，再逐段查询实时空位。成功两段、目标已完成或仅剩一个名额时不会额外抢占名额。

倒计时只选择一个固定场地且不允许其他场地时，若本机已保存该场地的完整结构，并与本次学校项目、校区和场馆一致，放号后前 2 秒内各候选的首次提交可直接使用结构参数；缓存不代表有空位，最终以学校提交响应为准。失败、窗口结束、缺字段、名称歧义或结构不匹配时回到学校查询。立即捡漏始终读取目标时段的实时空位。开始前仍核对学校订单。不限场地时优先尝试查询中有空位的场地；允许其他场地时保留所选场地顺序，其余场地按有空位优先排列。同场偏好的第二段也可提前保存暂定意图，首段换场后会校验并替换它。

数据保存在 App 私有目录；卸载会清除本地数据。覆盖安装前保留原签名，可从账号操作导出需要的登录文件。登录窗口仅允许学校 HTTPS 域名，密码在学校页面输入，App 不保存密码。导出文件包含登录权限，请勿公开上传。

## 架构

- `src/`：手机界面、本地状态、前台生命周期与共用请求队列。
- `../shared/`：与桌面共用的预约规则、协议与会话格式，不依赖桌面调度或文件系统。
- Android `CourtDevicePlugin`：原生 HTTP（独立 Cookie，不跟随重定向、只读接口网络异常时使用新连接重试一次，预约/取消请求不自动重试）、原子文件写入、预约发送前的小型持久化标记、只读请求取消、剪贴板、亮屏与前后台执行门控。
- Android `SchoolLoginActivity`：独立学校登录窗口、Cookie 捕获；`src/login.js` 验证新会话后再写入账号，失败保留旧记录。
- `www/`：构建产物，无真实账号、Cookie、配置或预约记录。

## 构建

```bash
cd mobile
npm ci
npm run apk
```

需要 JDK 21、Android SDK Platform 36 / Build Tools 36、可用网络。通过 `JAVA_HOME` 和 `ANDROID_HOME` 指定；本工作区也支持 `.build/mobile-tools/` 的独立构建工具。正常构建使用 Gradle wrapper；可选缓存 Gradle 8.14.3。输出复制到根目录 `dist/SZU-CourtBooker-Android.apk`。

```bash
# 根目录：桌面与手机规则回归（不预约）
node --test
# UI 预览资源
npm run build --prefix mobile
# 原生 HTTP、执行门控和文件恢复检查（需配置 JDK / Android SDK）
cd mobile/android && ./gradlew testDebugUnitTest
```

普通浏览器预览不提供学校网络和真实预约功能。WSL 界面验证必须使用 Windows Edge 专用实例，不能启动 Linux 浏览器。

目前验证范围：共用逻辑测试、登录写入/身份不匹配/失败回滚测试、前台中断/成功持久化的模拟测试、Edge 手机宽度界面检查，以及 APK 编译。没有连接 Android 真机；校内统一认证、验证码在 WebView 中的兼容性，Cookie 在原生请求中的实际有效性及亮屏/锁屏行为需要在你的手机上进行最终验收。

网络异常时，仅已知只读接口（含查询 POST）最多使用新连接重试一次，通常每次超时 8 秒；放号前场地准备使用更短超时，并在重试前检查准备窗口。结果未知的预约与取消不自动重发，先核对学校“我的预约”。同账号独立查询最多两路，预约 POST 在执行器与传输层均强制串行，跨项目和日期也不并发；前一单响应已保存后才推进后段，不提供双提交实验开关。按优先顺序完成查询、提交、保存，不让后段慢查询占住已就绪的前段。默认提交起始间隔 0.1 秒，查询不重新计时；捡漏按设置查询空位，不另加数秒延迟。明确频率拒绝后共享冷却，等待 1 秒、2 秒后的两次恢复尝试仍被拒绝则结束该账号本轮自动预约；这是客户端重试预算，学校触发和恢复规则仍未知，学校更长的 Retry-After 优先。已知拒绝不会记成未知订单，也不立即改抢其他场地。出队时复核状态、截止时间和最新 Cookie；不同账号互不阻塞。手动停止立即撤销原生执行令牌，阻止后续请求及查询重试；已经发出的预约仍等待结果并保存；只读请求可立即取消。诊断区分 JS 排队、原生排队、发送前记录写入、完整网络响应和本地结果保存耗时。

1.4 深度检查的复现过程、修复和验证限制见 [检查记录](../docs/android-audit-2026-09-20.md)。新增优先场地后继续尝试其余场地的可选开关；预约响应异常、存储故障与过期请求的处理已补充回归。
