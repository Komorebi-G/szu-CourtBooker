# SZU Court Booker · 深大场馆预约助手

一个在本机运行的深圳大学体育场馆预约工具。提前选好日期、时段和场地顺序，到点尝试预约；没有抢到时继续轮询，有空位就继续尝试。

提供 **Windows 桌面单文件版**和 **Android 前台版**，共用预约规则。桌面源码也支持 Linux。项目与学校无隶属关系，不保证抢到场地，不自动付款或退订。

[下载发行版](https://github.com/Komorebi-G/szu-CourtBooker/releases) · [桌面文档](desktop/README.md) · [Android 文档](mobile/README.md) · [问题反馈](https://github.com/Komorebi-G/szu-CourtBooker/issues)

## 先选适合你的版本

| | Windows 桌面版 | Android 版 |
|---|---|---|
| 安装 | 下载 EXE，放到固定文件夹 | 下载 APK，在手机上安装 |
| 运行依赖 | 不用安装 Node.js / npm | 不需要电脑或服务器 |
| 登录 | 浏览器登录或导入 Cookie / JSON | App 内学校登录或导入 Cookie / JSON |
| 多用户 | 支持，任务绑定账号 | 支持，方案绑定账号 |
| 到点执行 | 系统任务计划，可关闭管理网页 | 必须打开 App 并开始本次执行 |
| 熄屏 / 切后台 | 熄屏可继续；休眠唤醒受系统设置影响 | 执行时保持亮屏，切后台即中断 |
| 中断恢复 | 开始时间后 30 分钟内恢复，保留成功时段 | 重开不自动执行，保留结果供核对 |

**当前版本是预发布测试版。** Windows EXE 未做代码签名；Android APK 使用开发签名。Android 学校登录、验证码和设备生命周期尚待真机验收。不要把编译成功理解为所有机型都已经测试通过。iOS 暂不支持。

## 下载与开始使用

### Windows

1. 在 [Releases](https://github.com/Komorebi-G/szu-CourtBooker/releases) 下载 `SZU-CourtBooker-Windows-x64.exe`。无需下载 GitHub 自动生成的源码压缩包。
2. 把 EXE 放在固定位置，双击打开管理网页。程序不会弹黑色终端。
3. 在「账号管理」登录或导入账号；新建任务，选择用户、日期、项目、时段和场地顺序。
4. 保存草稿只保存设置；「保存并安排」经确认后才注册系统任务。开始时间已过时，会明确确认是否立即预约。
5. 安排后可以关闭管理网页。请保持电脑开机、用户已登录且联网；关机不能预约，休眠唤醒取决于硬件、电源计划和系统设置。

停止任务请用「停止并取消定时」，不要把关闭网页当作停止。安排定时后不要移动 EXE。更新前先停止正在执行的任务，再用新版替换原位置的 EXE；已经运行的旧进程不会自动升级。

### Android

1. 下载 `SZU-CourtBooker-Android-debug.apk` 并安装。已有同签名版本可覆盖安装；不要先卸载，否则本地数据会被清除。
2. 在「账号 → 学校登录」完成学校认证；识别 Cookie 并核对身份后保存。已有用户用「重新登录」更新，也可导入/导出完整登录 JSON。
3. 新建并保存预约方案，选中方案后点「执行所选」，明确选择等待放号或立即尝试。
4. 等待与执行期间保持 App 在前台，不锁屏、不切换 App。离开前台后会停止后续请求，返回不会自动续跑。
5. 在「结果」核对成功时段和订单，再到学校系统付款。重试前仅保留仍需预约的时段；结果未知的请求请先到学校核对。

登录网页若不能正常打开，可先从桌面版导出登录 JSON 再导入手机。使用不同签名构建的 APK 可能无法覆盖安装，卸载前先导出需要保留的信息。

## 预约规则

- 日期可选今天到未来第七天。一个任务可含多个候选时段，不是按星期循环执行。
- 固定放号时间为预约日期前一天北京时间 **12:30**。桌面可另设开始时间捡漏；保存任务本身不下单。
- 按点击顺序尝试场地，数字表示优先级。勾选「优先同一场地」后，连续的后一时段优先尝试前一时段已成功的场地；失败再回到原顺序，不会为换场退订。排球默认开启，羽毛球默认关闭。
- 同一执行批次内，同一学校账号、同一项目、同一天累计成功 **两个时段**后正常结束，其余时段作为候选，不再提交。并发任务共享计数；不同用户、项目和日期独立计数。
- 桌面中断恢复保留成功时段并计入上限。历史已结束任务不作为新一轮的本地名额限制，取消学校预约后可以重新测试；学校已有预约及最终限制以学校接口为准。
- 新建任务默认 **0.1 秒**轮询间隔，指一轮尝试结束后的等待时间，不代表每秒一定发出 10 次请求。预约请求串行发送，网络耗时另计；已有任务保留原间隔。
- 不自动付款、不自动退订，不绕过学校身份认证、名额或时间限制。

桌面恢复例子：12:30 开始、持续 2 分钟，12:45 启动电脑仍可补跑，并从实际开始执行 2 分钟；超过 13:00 不再补跑。正常完成、超时结束和手动停止的任务不会自动重复执行。详见 [桌面恢复说明](desktop/README.md)。

## 数据与隐私

账号、Cookie、任务和日志留在你的设备。Windows 单文件版存放于 `%LOCALAPPDATA%\SZUCourtBooker`；源码版使用本地 `config.yaml`、`.session.json`、`.data/`；Android 使用 App 私有目录。

导出的 Cookie / JSON 可以代表账号访问学校系统，请勿公开上传。仓库与发行包不含真实账号、Cookie、预约任务或订单。桌面管理服务没有远程认证，不要开放到公网；WSL 访问边界详见 [安全说明](SECURITY.md)。

项目规则依据已观察到的接口实现，学校接口可能变化。遇到提交超时等未知结果时，先核对学校订单，避免盲目重试。反馈问题时请脱敏，不要把登录 JSON 发到 Issue。

## 源码运行

需要 Node.js 22 或更新版本。以下命令均从仓库根目录执行：

```sh
npm ci
npm run web -- --no-open
```

访问终端显示的本机地址，默认 `http://127.0.0.1:4173`。首次启动自动建立空白配置；不会生成预约任务。Linux 的后台定时需要可用的 `systemd --user`，WSL 使用 Windows 任务计划程序。macOS 暂无经过验证的系统定时支持。

```sh
# 不访问学校的自动化测试
npm run check

# Android 界面构建
npm ci --prefix mobile
npm run build --prefix mobile

# Windows x64 单文件构建
npm run build:windows

# Android APK：另需 JDK 21 与 Android SDK 36
npm run apk --prefix mobile
```

Windows 打包需要与当前 Node 同版本的 Windows x64 `node.exe`；用 `SZU_WINDOWS_NODE` 指定路径。详见 [桌面文档](desktop/README.md)、[Android 文档](mobile/README.md) 与 [开发约定](CONTRIBUTING.md)。npm 只用于开发和构建，发行包的使用者不需要它。

## 仓库结构

```text
desktop/
  src/          桌面管理服务、账号文件、系统调度与恢复
  web/          桌面管理界面
mobile/
  src/          手机界面、前台执行、学校登录状态保存
  android/      Android 原生工程与插件
  scripts/      手机构建脚本
shared/         两端共用的学校协议、预约规则与会话格式
src/            旧启动入口兼容层（保留已有定时项路径）
scripts/        桌面打包、登录和验收工具
test/           模拟数据自动化测试
docs/           发布流程与版本说明
```

本地的 `dist/`、`.build/`、`.data/`、`output/`、设计草稿和浏览器调试记录均不进入 Git。不复制两套预约核心，也不把桌面调度逻辑塞进手机版。

## 验证与限制

已通过预约规则、账号隔离、任务恢复、持久化等模拟测试，并完成 Windows Edge 手机宽度界面检查、Windows 独立包与系统调度链路检查。Android 包通过编译和签名校验，但没有连接真机完成学校认证与真实预约验收；物理休眠唤醒也未覆盖所有设备。

请只使用本人或明确授权的账号，并遵守学校场馆规则。缺陷与建议欢迎通过 [Issues](https://github.com/Komorebi-G/szu-CourtBooker/issues) 反馈。
