# 临场执行深度检查记录

本轮针对“Cookie 可能在等待期间失效”和临场执行改造，沿真实 HTTP、实际文件保存和独立进程生命周期检查。未读取真实登录 Cookie，未向学校提交预约。

## 复现并修复的问题

| 问题 | 修改前的复现证据 | 修复后的行为 |
| --- | --- | --- |
| 验证身份和提交身份可能不同 | 本地服务第一次返回 A、第二次返回 B；实际客户端发生额外身份读取，下单未固定使用已验证的身份 | API 包装保持原对象的方法接收者；立即执行只读取一次身份，下单表单 `YYRGH=A`。倒计时后的刷新仍重新核验，身份变化则终止 |
| 一个任务结果未知，其他任务仍下单 | 服务端收到第一单后断开 socket；原实现仍收到第二个任务的提交 | 同一管理实例的提交队列覆盖意图保存、HTTP 和结果保存。结果未知时先停止全部当前执行，再释放队列；保留待核对意图 |
| 成功结果无法保存，后续任务仍提交 | 收到第一单时把 `state.json` 替换成目录，真实原子 rename 报 EISDIR；原实现仍收到第二单 | 写盘失败停止全部当前执行；已知成功保留在管理进程内存供界面查看，磁盘上最后有效的提交意图仍用于核对 |
| 同账号多个客户端各自持有旧 Cookie | 两个真实 HttpClient 先读取相同会话；第一个请求刷新 ticket，第二个仍发送 `ticket=old`，并可能将旧值写回文件 | 桌面端同账号请求和会话保存共用串行队列；每次发送前读取最新会话，响应更新保存后才放行下一个请求。不同账号仍各自保存 |
| 停止操作被其他管理请求阻塞 | 独立管理进程收到一个不结束的分块 POST 请求，后续停止请求必须等它完成 | 停止和退出绕过普通修改队列，保留来源检查；慢请求未结束时停止也能完成，跨站停止仍被拒绝 |
| 半写入记录拖垮整个列表及旧定时清理 | 保留 job.json、缺失 state.json，模拟两次初始保存之间崩溃，原列表整体抛 ENOENT | 单条异常显示“记录损坏”，其他方案仍可查看；旧任务先写停止标记再清理定时入口 |
| 损坏记录无法删除，初始读取异常留下锁 | 直接执行半写入记录后检查 run.lock；删除损坏记录因读取 state.json 失败而中断 | 工作函数的外层 finally 释放锁；删除时保留原文件到 trash。损坏记录若仍有存活进程的执行锁，则拒绝移动 |

前四个核心故障场景中的身份、断线、写盘失败和半写入记录，在修改前均运行失败；Cookie 场景和损坏记录删除随后分别复现失败，再修复。

## 额外检查的执行边界

- 启动验证成功、等待期间登录失效：真实 HTTP 返回登录重定向，放号时重新验证失败，提交数为零。
- 会话排队期间停止：同账号的查询占用队列时取消预约；队列恢复后仍不发送，返回 `REQUEST_NOT_SENT`，不保留虚假的未知订单。
- 在途请求强杀：服务端已经收到提交、尚未回答时 SIGKILL 子进程；提交意图已在磁盘，重开真实管理进程显示中断，不重发。
- 独立进程正在执行时，另一个执行器被共享目录的锁拒绝，不发送第二单。
- 未知结果和保存错误会停止当前管理实例中其他正在执行的任务，包含其他账号；重新操作前需要自行核对学校预约。

## 验证方法

专项位于 `test/deep-execution.test.js`。它使用本地 HTTP 服务器替代学校目的地址，但保留真实 CoreHttpClient / HttpClient、SzuVenueApi、任务执行器和文件保存。服务端检查实际请求参数、Cookie 和提交次数；进程场景通过 spawn 与 SIGKILL 验证。

```bash
node --test test/deep-execution.test.js
npm run check
npm run build --prefix mobile
```

专项 9 项及 Node 全量 116 项通过。Windows Edge 完成桌面流程和手机页面交互验证；API 写操作使用合成数据。已查看桌面倒计时和 390px 手机布局截图，包括损坏记录提示未阻挡其他方案。

浏览器脚本为 `scripts/verify-ui.js` 和 `scripts/verify-mobile-ui.js`，连接 Windows 专用 Edge 的 CDP 9334。运行时传入各自静态页面的实际 URL（包括 `/index.html`）。

## 结论的范围

这些结果证明所列故障场景得到处理，不代表已确定学校的 Cookie 过期规则。没有真实放号预约、Windows 安装包运行或 Android 真机验证；本轮未重新生成 EXE / APK。Cookie 串行更新是同一桌面进程内的保护，不是跨不同安装目录或外部脚本的全局会话锁。

磁盘持续不可写时，内存里的新成功结果不能保证在进程退出后保存。遇到“结果待确认”或存储错误，仍需核对学校“我的预约”，不能据本地状态认定下单失败。
