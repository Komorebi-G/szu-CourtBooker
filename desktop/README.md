# 桌面版使用与构建

深圳大学体育场馆预约助手。网页用于管理任务，独立后台执行器负责预约，日志和结果保存在本机。预约使用已经打通的学校 HTTP 接口，浏览器仅用于人工登录。

本文命令均在仓库根目录执行。返回 [项目首页](../README.md)。

## 启动

### Windows 单文件版（推荐日常使用）

双击 `dist/SZU-CourtBooker.exe`，无需安装 Node.js、npm、Python 或项目依赖。程序内置运行时，约 93 MiB；首次运行自动解压应用缓存，管理页面在本机浏览器打开。exe 使用 Windows GUI 子系统，后台预约不弹黑色终端。

请先把 exe 放在 Windows 本地盘的固定位置，再安排任务。账号、配置、任务和日志保存在 `%LOCALAPPDATA%\SZUCourtBooker`，不在 exe 旁边。包内不包含你的 Cookie 或已有任务。旧版用户可在账号管理导出登录 JSON，然后在 exe 版导入；原任务仍在旧数据目录，不会自动迁移或重复安排。构建尚未代码签名。

### 源码运行（Windows / Linux / WSL）

需要 Node.js 22 或更新版本。首次安装依赖：

```bash
npm install
```

日常 Windows 原生运行（项目放在 Windows 本地盘）双击 `start.cmd`；Linux/WSL 执行 `bash start.sh`。当前项目位于 WSL 时继续从 WSL 启动，定时任务会自动接入 Windows。也可以直接运行，日常不需要 npm：

```bash
node src/web-server.js
# 不自动打开浏览器：
node src/web-server.js --no-open
```

访问 <http://127.0.0.1:4173>。Windows 源码启动入口也支持项目内 `runtime/node.exe`。

普通 Windows/Linux 默认监听回环地址；WSL 为兼容 Windows localhost 转发监听 `0.0.0.0`。本版没有远程访问认证，不应暴露到公网。界面支持手机宽度，但手机远程管理、HTTPS 和身份验证属于后续扩展。

## 使用

1. 点击右上角账号管理。支持多个用户分别登录，或导入登录 JSON 文件、cURL、Cookie 字符串。可以完整查看、复制或导出当前用户的登录 JSON，舍友发送同格式即可导入。不保存账号密码。
2. 新建任务，选择执行用户、今天至未来第七天的预约日期、项目和多个时段。安排时验证学校身份，执行前再次核对；不会因为界面切换用户而换号预约。
3. 按优先顺序点击场地。数字与上方顺序条显示真实尝试顺序；再次点击取消。每个任务独立保存场地选择。
4. 设置开始时间、重试间隔与最长持续时间。默认开始时间是预约日期前一天 12:30；已放号可明确选择立即预约，也可另设捡漏时间。所有时间均为北京时间。
5. “保存草稿”不会安排执行。“保存并安排”后核对并确认，系统定时项注册成功才显示“已安排”。开始时间已过会明确确认“立即预约”，不会暗中立即下单。

“检查配置”只验证登录、项目解析和场地目录，绝不下单，也不表示已安排定时。配置检查不保证学校一定开放该日期、时段或场地。

可以多选候选时段，每个时段争取一个场地。同一执行批次内，同一学校账号、同一项目、同一天合计成功两个时段后正常结束，不再提交剩余候选；并发任务共享计数，不同用户、项目和日期独立计数。中断恢复时已成功时段计入上限。不根据历史已结束任务拦截新执行，在学校取消预约后可以再次安排；不自动付款或取消已成功预约。同一任务正在执行时，仍需先停止才能重新安排。

“优先同一场地”按任务设置，排球默认开、羽毛球默认关。开启后按时间顺序处理：连续的后一时段先尝试前一时段成功的场地，再尝试原顺序中的其他场地。如果前一时段没有成功、或者时段不相邻，沿用原顺序。优先同场不要求同场成功，也不会因此退订。一个时段尝试一轮后继续后面的时段，不会一直阻塞后面的预约。

重试间隔是**一轮尝试结束后**的等待时间，新建任务默认及最小 0.1 秒，最大一小时，请求仍经过串行队列。已有任务保留自定义间隔。持续时间最长一天。捡漏可设置较长间隔和持续时间。

## 关闭网页后如何执行

```text
网页保存任务快照 → 系统定时项唤起统一 dispatcher
                            ↓
               同一后台进程管理多个任务
                            ↓
               共用预约请求队列（一次一个请求）
                            ↓
               本地状态/日志文件 ← 网页轮询读取
```

源码版任务快照、执行状态和日志保存在 `.data/jobs/<记录编号>/`；exe 版位于 `%LOCALAPPDATA%\SZUCourtBooker\data\jobs\`。日志保留最近 500 条，成功记录另外保存。关闭网页或点击“退出管理服务”均不停止已安排的预约；再次打开后从文件恢复显示。系统定时项提前两分钟唤起程序，准备目录和时钟；不会在设定开始时间前主动提交预约。多个定时项可以同时唤起同一个执行器，进程锁确保只运行一份，共用请求队列协调任务。所有待执行任务结束或取消后，后台进程自动退出。

Windows 使用当前用户的任务计划程序，设置 `WakeToRun`、允许电池运行和错过后启动。需要保持 Windows 用户已登录、联网、exe 路径不变（源码版则需项目与 Node 路径不变）。实际休眠唤醒取决于硬件和电源计划是否允许唤醒定时器；熄屏不影响运行，关机不能执行。本机验证了 Windows → WSL 启动链路，以及管理服务退出后 Windows 定时启动独立 exe 并落盘日志，尚未实测物理休眠唤醒。

普通 Linux 使用持久的 `systemd --user` 定时器，需要 systemd 用户服务可用、保持登录和机器唤醒；本版不申请 root 权限配置 Linux 休眠唤醒。WSL 使用 Windows 任务计划程序，通过 `wsl.exe` 启动当前发行版的执行器。

定时任务的补跑/恢复窗口固定为「开始时间＋30分钟」，与最长持续时间分开：例如 12:30 开始、持续2分钟，12:45 开机仍允许执行，并从实际开始重新尝试2分钟；超过13:00不补跑。执行中断后在窗口内恢复，保留已经成功的时段，只尝试剩余时段。全部完成、正常超时结束或手动停止的任务不会重复执行。

新版 Windows 定时项同时注册当前用户登录触发，重新开机登录后可恢复；Linux 用户定时器增加用户服务启动触发。旧版已经登记的系统任务需要在新版中停止后重新安排，才能获得登录恢复触发；仅替换 exe 不会改写旧系统定时项。关机仍不能执行，唤醒仍取决于硬件和电源配置。

发送预约前持久保存请求意图。重启时，结果未知的请求先通过学校「我的预约」核对；只接受匹配时段、场地、项目的有效订单，取消订单不算成功。无法确认时跳过该时段并提示人工核对，继续其他明确未成功的时段，不盲目重发。旧版中断记录缺少请求意图时需要手动核对后重建剩余时段。

Windows 调度设置参考：[微软任务设置文档](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset)、[任务身份与登录类型](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtaskprincipal)。

## 停止与清理

- **停止并取消定时**：写入持久停止标记并移除系统定时项，中断等待和后续尝试。已经发出的请求会等待返回并保存结果，不强杀进程丢失成功信息。
- **删除单次记录**：在日志窗口删除该次记录及其系统定时项。执行中的记录须先停止。
- **删除任务**：删除草稿及关联执行记录，移除相关系统定时项；日志移入 `.data/trash/`，仍可恢复查看。不会取消学校预约。
- 定时执行意外中断后，可在开始后30分钟内恢复剩余时段；结果未知的时段需要先核对学校预约。手动停止不会自动恢复。

不要在任务已安排时移动 exe，或移动源码项目文件夹、替换 Node 路径；如需搬迁，先停止任务，搬迁后重新安排。登录过期需要重新登录。账号登录文件分别存储：默认用户沿用 `.session.json`，其他用户在数据目录的 `accounts/<用户编号>/session.json`。

## 项目结构

手机前台版见 [mobile/README.md](../mobile/README.md)。手机保存方案但不注册定时：需打开 App 进入本次执行，离开前台会中断。桌面系统调度和手机前台执行共用预约规则，但生命周期独立。

| 文件 | 职责 |
|---|---|
| `desktop/web/` | 原生 HTML/CSS/JS 响应式界面，无前端构建框架 |
| `desktop/src/web-server.js` | 本地管理 API、校验、账号连接 |
| `desktop/src/accounts.js` | 多账号独立登录、JSON 导入导出与身份核对 |
| `desktop/src/jobs.js` | 持久任务快照、停止、记录读取与清理 |
| `desktop/src/native-scheduler.js` | Windows / WSL / Linux 系统定时适配 |
| `desktop/src/dispatcher.js` | 单进程锁、任务发现、共享预约请求队列 |
| `desktop/src/job-worker.js` | 单个任务的生命周期及日志落盘，由 dispatcher 调用 |
| `shared/runner.js` | 等待开始、场地优先级、同场偏好、多时段重试 |
| `shared/api.js` / `desktop/src/http-client.js` | 学校接口、登录 Cookie 和 HTTP 请求 |

保留旧 `config.yaml` 配置的读取能力：旧项目级场地偏好作为尚未编辑任务的默认选择；编辑后独立保存。旧提前提交和全局成功数量限制不再使用。旧配置不会自动变成系统定时任务，必须在 UI 中明确安排。

## 开发验证

```bash
npm run check
# 或 node --test

# 真正注册一个无学校网络请求的系统测试任务，验证启动/日志/清理：
node scripts/verify-native-scheduler.js

# 构建 Windows x64 单文件，要求本机有同版本 Windows Node：
npm run build:windows
# WSL 上验证 exe 无外部依赖、退出管理服务后的原生 Windows 调度：
node scripts/verify-packaged.js

# 先启动管理服务与 Windows Edge 专用调试实例，再运行 UI 测试：
node scripts/verify-ui.js
```

UI 测试连接 `127.0.0.1:9334` 上的现有 Windows Edge，所有 API 写操作被模拟，不会预约或修改你的任务。截图写入 `output/playwright/`。系统调度测试故意使用不存在的登录文件，在访问学校前终止，验证完成会移除测试定时项。

调试用环境变量：`SZU_CONFIG`、`SZU_SESSION`、`SZU_DATA` 可指定独立数据路径；`PORT` 或 `--port` 指定管理端口。

CLI 仍可用于查看目录、检查登录和查询订单：

```bash
node src/cli.js session check
node src/cli.js catalog --date tomorrow
node src/cli.js orders --limit 20
node src/cli.js cancel <学校预约记录WID>
node src/cli.js run --now
```

最后一条只做配置检查。正式自动执行统一通过网页安排，以确保多个任务共用后台执行器。
