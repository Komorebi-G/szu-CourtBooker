# Android 前台版

安装 `dist/SZU-CourtBooker-Android.apk`。安装包自带界面和执行逻辑，不需要电脑、服务器、Node 或 npm。当前为开发签名测试包，未上架商店；iOS 原生适配尚未实现。

GitHub 发行附件名为 `SZU-CourtBooker-Android-debug.apk`。返回 [项目首页](../README.md)。

## 使用

需要 Android System WebView 109 或更新版本；组件过旧时显示更新提示。

1. 在「账号 → 学校登录」打开校内登录页，完成认证并进入场馆页面后，核对当前账号，点击「完成登录」获取 Cookie，再验证身份并保存。已有用户点击「重新登录」更新会话，登录错号或取消时不会覆盖原账号。仍可导入 Cookie、cURL、JSON 文件，以及查看/复制完整登录 JSON。多账号独立保存。
2. 在「方案」选择用户、今天至未来第七天的日期、项目、多时段和场地顺序。点击场地的数字表示尝试优先级。可勾选「优先同一场地」。另可勾选「允许尝试其他场地」：每轮先按所选顺序尝试，再尝试本项目场馆内其余场地；默认关闭，旧方案仍只尝试已选场地。场地列表先汇总各参考日期与此前读到的有效时段，再在每个已开放参考日期补查这些时段，并保留此前读到的场地和时段；满员或暂不可用的条目仍可作为方案候选。页面显示参考日期及是否含历史目录；目录不是目标时段的实时余量。
3. 保存方案不下单。点击方案的「开始倒计时 / 立即尝试」单独启动，或勾选多个可执行方案点击「执行所选」，默认按各方案放号时间执行：已放号的立即尝试，今天待放号的等到 12:30。也可统一选择「等待放号」或「立即尝试」；不允许提前隔夜守候。确认后各账号独立联网预检，同一账号只准备一次；慢账号不挡住已就绪账号，失效账号单独报错，其他账号继续，执行期间不弹出学校登录窗口；放号前最后 15 秒复核登录与订单，在准备窗口内预读候选时段并保存首单意图，到点提交首选；临近放号再次估计时钟偏差，准备时目录尚未开放或为空则到点重读。更早日期可以保存方案。请临近放号重新验证或登录，不依赖隔夜 Cookie。
4. 等待和执行期间自动保持亮屏。请勿锁屏或切换 App。原生层在离开前台时使本次执行令牌失效，返回后不会自动续跑。已发出的请求可能仍完成，成功结果会保存；结果未知时请到学校核对，不盲目重试。
5. 「结果」保留成功时段、订单编号和最近 300 条日志；最近 50 次执行常驻主状态，已结束且无未知请求的更早记录归档到独立文件，可在结果页分批读取。未核实请求和当前方案的最新结果继续常驻。可查看并复制脱敏诊断 JSON，保留原参数、构建标识、匿名账号分组、全程计数和各时段摘要，超出 300 条的缺失事件会注明。重新打开 App 会把未结束记录标记为中断，不会自动预约。编辑过方案时可在结果页「核对此次执行」，使用当时的方案快照。重试前点击方案的「核对与重试」，只读查询学校订单，另存剩余方案；原方案和当时的结果保留；匹配到学校订单的请求另记为已核实，尚未对应的请求须人工核对，确认无订单后才解除重复提交限制。

正式执行时，空目录在执行窗口内重试，已开始的时段会跳过。结果区分全部成功、部分成功、达到名额上限但本方案零成功、时段过期、未约到和错误。账号异常或学校明确但无法识别的业务拒绝会显示原始原因，并阻止同账号、项目、日期的其他方案继续提交；已发送但结果未知的请求需先到学校“我的预约”核对。

没有自动付款、退订、后台定时、开机启动或后台保活。长时间亮屏捡漏会耗电。数据保存在 App 私有目录；卸载会清除本地数据，请提前复制需要的登录和结果。停止/删除本地记录不会取消学校预约。

新建方案默认重试间隔 0.1 秒，指一轮尝试结束后的等待时间；同一学校账号串行提交，不同账号独立并行。开始预约前重新只读核对学校订单；同一学校账号、项目、日期的学校有效预约与本批次新成功合计两个时段后，剩余候选不再提交。并发方案共享核对和计数，不同项目、日期、用户独立计数，不直接把本地历史记录计入名额。查询失败或订单状态无法识别时停止相关方案，不视为空订单。未知响应只停止对应账号；本地保存失败停止整个批次。结果页和恢复记录保留全部在途请求。已有方案保留原来设置的间隔。

学校登录使用独立、无 App 原生桥接的 WebView，只允许学校 HTTPS 域名导航。窗口可沿用此前学校会话，换号 / 重试时清理窗口 Cookie，不删除已保存账号；新增用户先确认识别到的姓名和学号尾号，重复身份不能重复绑定。密码在学校页面填写，App 不保存密码；登录后仅调用身份与日期查询接口，不预约。需要跳转到校外第三方的登录方式暂不支持，可使用学校账号密码或 JSON 导入。

预约目标支持「任选一段」「连续两段」「任意两段」，未指定目标的旧方案只有一个候选时段时按任选一段执行，多个候选时段按任意两段；显式选择任意两段必须有两个互不重叠的候选时段。连续目标只补相邻时段，可能只成功一段，不退订。场地优先顺序支持上移 / 下移，提供放号和慢速捡漏预设；过期方案编辑时保留旧日期，必须主动选择新日期。结果显示每个时段的状态，并提供学校核对 / 付款入口。

## 工作台与方案复用

首次使用沿「学校登录 → 创建方案 → 手动执行」显示当前步骤，登录后返回方案页；空页面隐藏重复新建入口、筛选和搜索。首次保存不会默认勾选批量执行，页面明确提示手动开始。只有过期方案时引导重新选日期。执行过后首页以单列方案卡片为主，提供近期、进行中、需处理、全部筛选和搜索。仅在需要登录、执行中或有待处理结果时显示简短提示；正常状态不展示重复概览。过期方案保留在「全部」；结果未知的方案始终保留在「需处理」，不会因为日期过去而隐藏。卡片状态按方案自己的执行结果显示；同一批其他方案的失败不会把已完成方案显示成失败，修改日期、账号、场地或执行设置后不复用旧结果。

卡片「更多」里的「再约一次」先打开编辑器，保留账号、时段、场地顺序和偏好，清除原执行身份与相邻场地锚点。过去或超出可选窗口的日期改为明天；仍在窗口内的未来日期保留，需自行确认。关闭不会保存，保存也不会执行。卡片的「方案详情」可展开完整场地顺序与重试参数，刷新保留展开状态。「更多」支持点击外部或 Esc 收起，并根据屏幕空间向上展开。表单显示放号时间和选择汇总，关闭编辑器、换日期或启动执行时会取消旧目录查询，避免占用该账号的抢场连接。

单方案和批量执行都保留真实预约确认。未来放号日、已完成、时段已开始及有未知订单的方案不能直接勾选启动；可编辑、复用或核对。只有选中可执行方案时才出现底部批量栏，切换到结果或账号页时隐藏，避免遮挡内容。结果页导航标记正在执行或待核对的记录。

## 架构

- `src/`：手机界面、本地状态、前台生命周期与共用请求队列。
- `../shared/`：与桌面共用的预约规则、协议与会话格式，不依赖桌面调度或文件系统。
- Android `CourtDevicePlugin`：原生 HTTP（独立 Cookie，不跟随重定向、只读接口网络异常时使用新连接重试一次，预约/取消请求不自动重试）、原子文件写入、预约发送前的小型持久化标记、只读请求取消、剪贴板、亮屏与前后台执行门控。
- Android `SchoolLoginActivity`：独立学校登录窗口、Cookie 捕获；`src/login.js` 验证新会话后再写入账号，失败保留旧记录。
- `www/`：构建产物，无真实账号、Cookie、配置或预约记录。

## 构建

```bash
cd mobile
npm ci
npm run apk
```

需要 JDK 21、Android SDK Platform 36 / Build Tools 36、可用网络。通过 `JAVA_HOME` 和 `ANDROID_HOME` 指定；本工作区也支持 `.build/mobile-tools/` 的独立构建工具。正常构建使用 Gradle wrapper；可选缓存 Gradle 8.14.3。输出复制到根目录 `dist/SZU-CourtBooker-Android.apk`。

```bash
# 根目录：桌面与手机规则回归（不预约）
node --test
# UI 预览资源
npm run build --prefix mobile
```

普通浏览器预览不提供学校网络和真实预约功能。WSL 界面验证必须使用 Windows Edge 专用实例，不能启动 Linux 浏览器。

目前验证范围：共用逻辑测试、登录写入/身份不匹配/失败回滚测试、前台中断/成功持久化的模拟测试、Edge 手机宽度界面检查，以及 APK 编译。没有连接 Android 真机；校内统一认证、验证码在 WebView 中的兼容性，Cookie 在原生请求中的实际有效性及亮屏/锁屏行为需要在你的手机上进行最终验收。

网络异常时，仅已知只读接口（含查询 POST）最多使用新连接重试一次，通常每次超时 8 秒；放号前场地准备使用更短超时，并在重试前检查准备窗口。预约与取消不自动重发；结果未知时先核对学校“我的预约”。同一账号的原生请求串行，出队时复核状态与截止时间，并更新 Cookie；不同账号仍可并发查询。手动停止会立即撤销原生执行令牌，阻止后续请求及查询重试；已经发出的预约仍等待结果并保存；只读请求可立即取消，原生层中止对应网络调用，不会取消已发出的预约。

1.4 深度检查的复现过程、修复和验证限制见 [检查记录](../docs/android-audit-2026-09-20.md)。新增优先场地后继续尝试其余场地的可选开关；预约响应异常、存储故障与过期请求的处理已补充回归。
