# v0.3.0 · 临场执行与登录态可靠性修复

提前保存方案，放号当天验证登录，再手动开始本次倒计时。此版本移除系统定时入口和中断后自动补跑，避免沿用前一天已经失效的登录态。

## 下载

- `SZU-CourtBooker-Windows-x64.exe`：Windows x64，自带运行时，无需安装 Node.js。
- `SZU-CourtBooker-Android-debug.apk`：Android 7.0+，开发签名版；内部版本 1.5，versionCode 6。
- `SHA256SUMS.txt`：附件 SHA-256 校验值。
- `LICENSES.zip`：项目及第三方许可证。

## 主要变化

- 桌面改为临场执行；保存方案不会自动预约。倒计时启动时验证登录，放号时再次核验身份；失效则停止并提示重新登录。
- 修复同账号多个桌面客户端使用旧 Cookie、把新 Cookie 覆盖回旧值的问题；修正 Cookie 有效期处理。
- 修复 API 包装造成验证身份与下单身份缓存分离的问题。
- 请求结果未知或执行记录保存失败时，停止当前管理实例中其他执行，保留成功结果或待核对信息。
- 停止操作不再被慢管理请求堵住；等待发送期间取消，不会在队列恢复后继续提交。
- 单条损坏记录不再阻断列表及旧定时清理；异常时清理执行锁，损坏记录删除时归档保留原文件。
- Android 修复部分成功状态、重开后的中断状态及未发送请求的结果标记；保留前台执行要求。
- 包含此前桌面启动及缓存修复、Android 网络可靠性修复和可选其余场地支持。

## 升级说明

Windows 更新前先停止旧版本执行，再替换 EXE。新版启动时停用当前数据目录中的旧系统定时项，不自动重跑历史任务。关闭浏览器标签不停止执行；使用“退出并停止执行”结束当前任务。执行期间保持程序运行、电脑醒着且联网。

Android 使用原开发签名，可覆盖安装同签名版本；切后台会停止后续提交，返回不会自动继续。登录态可能失效，需要临场验证；本次修复不代表已确定学校的 Cookie 失效规则。

出现“结果待确认”或存储错误时，先核对学校“我的预约”，不要直接认定失败后重复提交。磁盘持续不可写时，内存中的新结果无法保证在进程退出后保留。
