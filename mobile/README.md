# Android 前台版

安装 `dist/SZU-CourtBooker-Android.apk`。安装包自带界面和执行逻辑，不需要电脑、服务器、Node 或 npm。当前为开发签名测试包，未上架商店；iOS 原生适配尚未实现。

GitHub 发行附件名为 `SZU-CourtBooker-Android-debug.apk`。返回 [项目首页](../README.md)。

## 使用

1. 在「账号 → 学校登录」打开校内登录页，完成认证后自动获取 Cookie，核对身份并保存。已有用户点击「重新登录」更新会话，登录错号或取消时不会覆盖原账号。仍可导入 Cookie、cURL、JSON 文件，以及查看/复制完整登录 JSON。多账号独立保存。
2. 在「方案」选择用户、今天至未来第七天的日期、项目、多时段和场地顺序。点击场地的数字表示尝试优先级。可勾选「优先同一场地」。另可勾选「优先场地未成功时，继续尝试其余场地」：每轮先按所选顺序尝试，再尝试本项目场馆内其余场地；默认关闭，旧方案仍只尝试已选场地。学校目录可缓存；目录不是实时余量，实际能否预约以学校为准。
3. 保存方案不下单。勾选一个或多个方案，点击「执行所选」，明确确认「等待放号」或「立即尝试」。等待放号固定为预约日期前一天 12:30；提前打开后会立即联网校验身份、读取目录和校准时钟，再在前台倒计时，到点才提交。页面会显示具体放号日期（北京时间），建议临近放号时执行，避免整夜亮屏等待。
4. 等待和执行期间自动保持亮屏。请勿锁屏或切换 App。原生层在离开前台时使本次执行令牌失效，返回后不会自动续跑。已发出的请求可能仍完成，成功结果会保存；结果未知时请到学校核对，不盲目重试。
5. 「结果」保留成功时段、订单编号和最近 300 条日志，可查看并复制完整记录 JSON。重新打开 App 会把未结束记录标记为中断，不会自动预约。重试前编辑方案，只保留需要再次尝试的时段。

没有自动付款、退订、后台定时、开机启动或后台保活。长时间亮屏捡漏会耗电。数据保存在 App 私有目录；卸载会清除本地数据，请提前复制需要的登录和结果。停止/删除本地记录不会取消学校预约。

新建方案默认重试间隔 0.1 秒，指一轮尝试结束后的等待时间，请求仍串行。可以多选候选时段；同一轮执行中，同一学校账号、项目、日期合计成功两个时段后正常结束，剩余候选不再提交。不同项目、日期、用户独立计数，不把历史已结束执行记录作为名额限制。已有方案保留原来设置的间隔。

学校登录使用独立、无 App 原生桥接的 WebView，只允许学校 HTTPS 域名导航。每次登录清空这个窗口的旧 Cookie，不删除已保存账号。密码在学校页面填写，App 不保存密码；登录后仅调用身份与日期查询接口，不预约。需要跳转到校外第三方的登录方式暂不支持，可使用学校账号密码或 JSON 导入。

## 架构

- `src/`：手机界面、本地状态、前台生命周期与共用请求队列。
- `../shared/`：与桌面共用的预约规则、协议与会话格式，不依赖桌面调度或文件系统。
- Android `CourtDevicePlugin`：原生 HTTP（独立 Cookie，不跟随重定向、只读接口网络异常时使用新连接重试一次，预约/取消请求不自动重试）、原子文件写入、剪贴板、亮屏与前后台执行门控。
- Android `SchoolLoginActivity`：独立学校登录窗口、Cookie 捕获；`src/login.js` 验证新会话后再写入账号，失败保留旧记录。
- `www/`：构建产物，无真实账号、Cookie、配置或预约记录。

## 构建

```bash
cd mobile
npm ci
npm run apk
```

需要 JDK 21、Android SDK Platform 36 / Build Tools 36、可用网络。通过 `JAVA_HOME` 和 `ANDROID_HOME` 指定；本工作区也支持 `.build/mobile-tools/` 的独立构建工具。正常构建使用 Gradle wrapper；可选缓存 Gradle 8.14.3。输出复制到根目录 `dist/SZU-CourtBooker-Android.apk`。

```bash
# 根目录：桌面与手机规则回归（不预约）
node --test
# UI 预览资源
npm run build --prefix mobile
```

普通浏览器预览不提供学校网络和真实预约功能。WSL 界面验证必须使用 Windows Edge 专用实例，不能启动 Linux 浏览器。

目前验证范围：共用逻辑测试、登录写入/身份不匹配/失败回滚测试、前台中断/成功持久化的模拟测试、Edge 手机宽度界面检查，以及 APK 编译。没有连接 Android 真机；校内统一认证、验证码在 WebView 中的兼容性，Cookie 在原生请求中的实际有效性及亮屏/锁屏行为需要在你的手机上进行最终验收。

网络异常时，仅已知只读接口（含查询 POST）最多使用新连接重试一次，每次超时 8 秒。预约与取消不自动重发；结果未知时先核对学校“我的预约”。手动停止会立即撤销原生执行令牌，阻止后续请求及查询重试；已经发出的请求仍等待结果并保存。

1.4 深度检查的复现过程、修复和验证限制见 [检查记录](../docs/android-audit-2026-09-20.md)。新增优先场地后继续尝试其余场地的可选开关；预约响应异常、存储故障与过期请求的处理已补充回归。
